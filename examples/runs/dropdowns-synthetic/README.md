# dropdowns-synthetic — deterministic A/B replay archive

Hand-authored, zero-model-spend fixture corpus that exercises the scoring and
`gate` stack end to end. It records a skill upgrade that made things **worse**,
so the gate must catch it. Nothing here calls a model: every score is composed
from recorded per-assertion signals under the `skill_behaviour` gate weights
(§16.1), and `replay` re-derives the same scorecards from the raw event logs.

## Layout

```
benchmark/                 self-contained skill_behaviour benchmark
  benchmark.json           evaluation_type=skill_behaviour, judge-calibrated
  cases.jsonl              4 cases (native, react, portal, distractor)
  labels/golden.jsonl      human verdicts == recorded judge verdicts (kappa 1.0)
baseline-v1/               matrix run of fixtures/synthetic-skill/v1  (gate --baseline)
candidate-v2/              matrix run of fixtures/synthetic-skill/v2-regressed (gate --run)
  matrix_summary.json      §15.1 entry point (2.0.0)
  events.jsonl             §15.2 wide-event stream (1.0.0)
  combos/<engine>__<model>__default__<version>/
    cases.jsonl
    runs/combo-run-<engine>-<version>/
      scorecard.json       §15.3 (2.1.0), signals[] shaped like ScoredSignal
      events.jsonl
      cases/<case>.json               case rolled up across seeds
      seeds/<0..1>/cases/<case>.json  per-seed RunResult
      seeds/<0..1>/workspace/<case>/.gh-aw-advisory/
        <engine>.raw.jsonl   engine-native stream (claude JSON / codex exec)
        trace.jsonl          normalised TraceEvent[] (frozen schema)
        prompt.md
        grading.json
```

Two recorded engines (`claude`, `codex`) run identical deterministic traces, so
`replay` output is byte-stable. Seeds = 2.

## The planted regression

`fixtures/synthetic-skill/v2-regressed/SKILL.md` tells the agent to click
without re-screenshotting the opened menu. On the native `<select>` that is
still fine; on the react-select-style widget and the portal-rendered menu the
blind click lands on late-arriving / absent geometry, so both
`trace:require_order(screenshot, click)` (trace_conformance) and the acceptance
check (task_outcome) fail.

## Expected gate verdict

`gate --run candidate-v2 --baseline baseline-v1` must **FAIL** (non-zero exit):

- Paired-by-case bootstrap 95% CI of the benchmark-score delta excludes zero
  (upper bound well below `-max_regression=0`) — a **significant** regression.
- Two cases flip pass→fail (`s-react`, `s-portal`): the `regression` bucket
  grows, which fails the upgrade protocol (§18.3) on its own.
- Both runs have `judge_disabled: false` and the benchmark ships a golden set
  with perfect agreement, so the runs are valid, judge-calibrated gate inputs
  (not rejected for "judge uncalibrated").
